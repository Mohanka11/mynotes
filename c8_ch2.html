1. Foundational Concepts: Data vs. Information

Understanding the distinction between raw input and organized output is fundamental to mastering database management.

Core Definitions

  • Data: Refers to raw, unprocessed facts and figures. It can exist as numbers, letters, images, or sounds, but lacks context on its own.
  • Information: Data that has been processed, structured, and given meaning (e.g., "10" is data; "10 students passed the exam" is information).
  • Database: A structured collection of related tables where data is stored in an organized and systematic manner. Everyday examples include a teacher's attendance register or a personal telephone directory.

2. Database Architectures and Types

Databases are categorized by their underlying complexity and the way they interconnect different data files.

Common Database Types

  • Flat Database: Stores information in a single tabular file without establishing relationships to other files (e.g., an MS Excel spreadsheet).
  • Relational Database (RDBMS): Organizes data into predefined tables that are linked via common key fields to create a unified system (e.g., MS Access, Oracle, FoxPro).
  • Distributed Database: Spread across multiple geographical locations or servers in a network, enabling concurrent multi-user access without interference.

3. Introduction to MS Access 2016

Microsoft Access 2016 is a powerful, user-friendly Relational Database Management System (RDBMS) included in the Microsoft Office suite.

The Structural Hierarchy of Data

  • Tables (The Container): The primary database object where all structured data for a specific topic is held.
  • Records / Rows (The Entries): A complete set of related data representing a single unit (e.g., all details of one student).
  • Fields / Columns (The Categories): Specific attributes or categories of data within a record (e.g., "Roll Number", "Phone Number").
  • Values: The individual data cells situated at the intersection of a row and a column.

6. Essential Keys and Relationships

Keys enforce data integrity and establish links across multiple tables in a relational database.

Key Classifications

  • Primary Key: A unique identifier for every record in a table; it cannot contain NULL (empty) values (e.g., Roll Number, Employee ID).
  • Candidate Key: Any field or set of fields that satisfies the prerequisites to become a Primary Key.
  • Foreign Key: A field in a table that references the Primary Key of another table, creating an active relational link.
Setting Relationships: Open the Relationships window, then drag a primary key field from one table and drop it onto the matching foreign key field in another table.

7. Data Manipulation and Navigation

Table Operations in Datasheet View

  • Add a Record: Go to the last row or click the New Record button and press Tab.
  • Add a Field: Right-click a column header → select Insert Field.
  • Update Data: Click directly into a target cell and type the new value.
  • Delete Data: Right-click a row or column header → select Delete Record or Delete Field.
  • Hide / Unhide: Right-click a column header to hide it from display or unhide previously hidden columns.
  • Move Fields: Click and hold a column header, then drag it horizontally to the desired position.

8. Sorting, Filtering, and Searching

These tools allow efficient data organization, extraction, and inspection within large datasets.

  • Sorting: Reorders records alphabetically or numerically in Ascending (A to Z, 0 to 9) or Descending (Z to A, 9 to 0) sequence.
  • Filtering: Temporarily hides non-matching records using a drop-down checklist on the field header.
  • Searching: Locates matching values quickly using the search box in the bottom navigation bar.
  • Filter vs. Query: Filtering is a temporary on-screen check, whereas a Query is a saved database object built for complex, repeatable multi-criteria data extraction.

9. Queries: Advanced Data Retrieval

A Query extracts and displays only those records and fields that meet specific, user-defined criteria (e.g., students with marks > 80).

Query Design Grid Elements

  • Top Pane: Shows source tables along with their field lists.
  • Design Grid (Bottom Pane): Contains rows that configure data output:
    • Field & Table Rows: Identify the specific fields and source tables being retrieved.
    • Sort Row: Determines display order (Ascending or Descending).
    • Show Checkbox: Toggles whether a field is visible in the final results.
    • Criteria / Or Rows: Defines conditional filter logic (e.g., >12 or ="Mumbai").
  • Execution: Click the Run button (red exclamation mark !) in the Results group on the Ribbon to display the query output.
